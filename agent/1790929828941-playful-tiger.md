  - **事实**：workbox `RegExpRoute` 匹配 **`url.href`（完整 URL）**，不是 pathname。所以 `config.mjs` 三条带 `^\/` 的规则 —— `:284 /^\/api\/.*/i`、`:310 /^\/[^/]+\/?$/i`、`:323 /^\/[a-zA-Z0-9_-]+(?:\/[a-zA-Z0-9_-]+)+\/?$/i` —— **对同源请求永远不可能命中**（href 以 `https://` 开头）。原「中文路由匹配不到」的诊断是错的，实为**谁都匹配不到**
  - **修法**：改**函数式 matcher**（`workbox-build` 对非字符串 pattern 走 `matcher.toString()` 内联进 `sw.js`，函数是受支持的）
  - **v5 硬约束**：函数 matcher **不能引用外层变量** —— `.toString()` 后没有闭包，引用 `const ASSET_RE` 会在 SW 里抛 `ReferenceError`。**正则必须内联在每个 matcher 内**
  - **v5 必须排除静态资源**：`workbox` 是「首条命中优先」，不排除的话 `:310`/`:323` 会把 `/assets/chunks/x.js`、`/fonts/iconfont/iconfont.css`、`/images/a/b.png` 抢进 NetworkFirst，`:336`/`:348`/`:360` 的 CacheFirst 再也接不到。**同时** `:310` 的 `[^/]+` 允许点号，会把 `/favicon.ico`、`/robots.txt`、`/rss.xml`、`/sitemap.xml`、`/manifest.webmanifest` 拉进 page-cache

    ```js
    // :284 —— API（无需后缀排除，/api/ 下本就无静态资源）
    { urlPattern: ({ url }) => url.pathname.startsWith("/api/"),
      handler: "NetworkFirst", options: { cacheName: "api-cache", /* ... */ } },

    // :310 —— 单段页面（排除根级带点文件）
    { urlPattern: ({ url }) =>
        /^\/[^/]+\/?$/.test(url.pathname) &&
        !/\.(?:js|mjs|css|map|json|txt|xml|ico|png|jpe?g|gif|svg|webp|avif|woff2?|ttf|otf|webmanifest)$/i.test(url.pathname),
      handler: "NetworkFirst", options: { cacheName: "page-cache", /* ... */ } },

    // :323 —— 多段页面（排除静态资源后缀）
    { urlPattern: ({ url }) =>
        /^\/[^/]+\/.+/.test(url.pathname) &&
        !/\.(?:js|mjs|css|map|json|txt|xml|ico|png|jpe?g|gif|svg|webp|avif|woff2?|ttf|otf|webmanifest)$/i.test(url.pathname),
      handler: "NetworkFirst", options: { cacheName: "post-cache", /* ... */ } },
    ```

  - `:297 /\.html$/i` 无 `^` 锚点，能命中，**保持不动**
  - **v6 两点知会**（非错误，供取舍）：
    1. 函数 matcher **不受 origin 限制**（旧正则只在匹配位置 0 才受理跨域）。跨域 CDN 里形如 `/npm/pkg@1/dist/style.css` 会被后缀排除挡住 ✓，但**无扩展名的跨域多段路径会被 post-cache 收编**。要收紧就在 matcher 里加 `sameOrigin &&`（matcher 参数确实带 `sameOrigin`）
    2. 排除列表按 `$` 锚定 pathname，将来若有 slug 正好以这些后缀结尾（如 `/posts/vue.js`）会不进缓存 —— **可接受，知会即可**
  - **v5 验收口径明确**：`/rss.xml`、`/sitemap.xml`、`/robots.txt` 被后缀排除后**不进任何运行时缓存**（走 precache 或网络）—— 这是**期望行为**，不是遗漏。`/api/status` 走 api-cache；中文标签页/分类页走 post-cache；`/fonts/*`、`/assets/*`、`/images/*`、根级 `/favicon.ico` 走 CacheFirst

### J. dev 中间件（N2）—— **v5 补回输入清洗半边，删掉错误示例**

- **事实**：`config.mjs:184-241` 是**裸插值**（无任何清洗）。`content.replace(re, \`$1${value}$2\`)` 是字符串替换，替换串里的 `$&`/`$'`/`` $` ``/`$n` 会被特殊解释
- **v4 订正**：`JSON.stringify` **堵不住** —— `$` 不是 JSON 需转义字符，且现有正则捕获组含引号（`/(siteVersion:\s*")[^"]*(")/`），整体替换会写出 `siteVersion: ""V1.3""`，破坏 `store/index.js`
- **v5 订正**：v4 的第一条示例 `(m, p1, p2) => p1 + data.siteVersion.replace(/\$/g, "$$$$") + p2` **是错的** —— 函数式替换的**返回值不再解释 `$`**，二次转义会把每个 `$` 写成两个。**只保留函数形式**：

  ```js
  content.replace(re, (_m, p1, p2) => `${p1}${data.siteVersion}${p2}`);
  ```

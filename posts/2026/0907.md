## 你现在应该处于什么状态

你能看到这篇文章，说明本地开发环境已经启动，模板也能够正常渲染。

现在不需要继续研究环境准备，也不建议马上修改 `.vitepress/theme/` 中的组件代码。当前最重要的工作是把模板里的示例信息替换成你自己的内容。

建议按照下面的顺序修改：

1. 站点名称、作者和域名。
2. 首页侧边栏与生日信息。
3. 顶栏导航和页脚链接。
4. Logo 与 favicon。
5. 示例文章和普通页面。
6. 评论、搜索、音乐等第三方服务。
7. 部署地址与发布检查。

每完成一组就保存并刷新浏览器。这样出现错误时，很容易知道是哪一次修改造成的。

## 一、先完成最小配置

如果只想尽快让网站看起来像自己的，先修改 `themeConfig.mjs` 中的 `siteMeta`。

```js
siteMeta: {
  title: "小明的博客",
  description: "记录编程、学习和生活",
  logo: "/images/logo/favicon-256.png",
  site: "https://blog.example.com",
  author: {
    name: "小明",
    cover: "/images/logo/favicon-256.png",
    email: "xiaoming@example.com",
    link: "https://blog.example.com",
  },
},
```

### 字段说明

| 字段           | 修改内容   | 显示位置                |
| -------------- | ---------- | ----------------------- |
| `title`        | 博客名称   | 浏览器标题、页头、PWA   |
| `description`  | 一句话介绍 | 首页、侧边栏、SEO       |
| `logo`         | 站点 Logo  | 导航和站点展示          |
| `site`         | 正式域名   | canonical、sitemap、RSS |
| `author.name`  | 作者名称   | 侧边栏、页脚            |
| `author.cover` | 作者头像   | 作者展示                |
| `author.email` | 联系邮箱   | 邮件链接                |
| `author.link`  | 作者主页   | 页脚作者链接            |

接着修改：

```js
icp: "",
since: "2026-10-25",
```

- `icp` 是备案信息，不需要备案时保留空字符串。
- `since` 是建站日期，会显示在站点统计或相关组件中。

## 二、修改首页侧边栏

首页侧边栏中的组件大多由 `themeConfig.mjs` 的 `aside` 控制。这里不要改变组件顺序，只修改数据。

### 1. 欢迎语

```js
aside: {
  hello: {
    enable: true,
    text: "欢迎来到<strong>小明的博客</strong>。这里记录我的学习、开发与生活。",
  },
},
```

`text` 中可以使用 `<strong>`、`<br>` 等简单 HTML 标签，但不要写复杂脚本。

### 2. 生日倒计时

生日位置保持为“生日”，只修改日期：

```js
countDown: {
  enable: true,
  data: {
    name: "生日",
    date: "2000-08-16",
  },
},
```

这里填写你希望展示的生日。不要把 `name` 改成“建站”“纪念日”等其他含义，除非你确实想把该位置改成其他倒计时。

### 3. 时间线

```js
timing: {
  enable: true,
  items: [
    {
      icon: "🎂",
      name: "小明",
      event: "生日",
      date: "2000-08-16",
      includeStart: true,
    },
    {
      icon: "🚀",
      name: "博客",
      event: "建站",
      date: "2026-10-25",
      includeStart: true,
    },
  ],
},
```

可以添加多个项目，但第一次使用时建议保留一到两个，避免首页信息过密。

### 4. 其他侧边栏组件

- `aside.toc`：文章目录。
- `aside.tags`：标签云。
- `aside.siteData`：站点数据。
- `aside.weather`：天气。
- `aside.HelloGithub`：HelloGitHub 热榜。

暂时用不到的组件可以关闭，但不要删除配置字段。

## 三、修改顶栏导航

当前顶栏保持原有结构：

- `文库`：文章列表、全部分类、全部标签。
- `友链`：友情链接、畅所欲言。
- `我的`：关于作者、关于本站、回到主页、服务状态。

### 修改导航名称

```js
{
  text: "我的",
  items: [
    { text: "关于我", link: "/pages/about-me", icon: "contacts" },
    { text: "关于博客", link: "/pages/about-website", icon: "code" },
    {
      text: "回到主页",
      link: "/",
      icon: "home",
      mobileOnly: true,
    },
    {
      text: "服务状态",
      link: "https://status.example.com",
      icon: "chart",
      mobileOnly: true,
    },
  ],
},
```

只需要修改文字和链接。除非确实要调整菜单，否则不要移动或删除 `mobileOnly` 项目。

### 修改左侧项目菜单

```js
navMore: [
  {
    name: "项目",
    list: [
      {
        icon: "/images/logo/favicon-256.png",
        name: "小明的博客",
        url: "/",
      },
      {
        icon: "/images/logo/favicon-256.png",
        name: "我的项目",
        url: "https://project.example.com",
      },
    ],
  },
],
```

`navMore` 用于导航栏左侧的项目入口。没有其他项目时，只保留主站入口也可以。

## 四、修改页脚

### 1. 社交链接

```js
footer: {
  social: [
    { icon: "email", link: "mailto:xiaoming@example.com" },
    { icon: "github", link: "https://github.com/xiaoming/blog" },
  ],
},
```

主题注释中建议社交链接保持偶数个。可以删除不需要的平台，但建议保留完整的 `{ icon, link }` 对象格式。

当前支持的图标名称包括：

- `email`
- `qq`
- `telegram`
- `twitter-x`
- `github`
- `bilibili`

### 2. 页脚站点地图

```js
sitemap: [
  {
    text: "博客",
    items: [
      { text: "近期文章", link: "/" },
      { text: "文章归档", link: "/pages/archives" },
    ],
  },
  {
    text: "关于",
    items: [
      { text: "关于我", link: "/pages/about-me" },
      { text: "隐私政策", link: "/pages/privacy" },
    ],
  },
],
```

每个分组都是：

```js
{
  text: "分组名称",
  items: [
    { text: "链接名称", link: "/网址" },
  ],
}
```

不要忘记修改 `服务` 分组中的状态页、资源下载和反馈邮箱等外部链接。

## 五、替换 Logo 和 favicon

模板使用以下图片：

```text
public/images/logo/favicon-32.png
public/images/logo/favicon-96.png
public/images/logo/favicon-256.png
public/images/logo/favicon-512.png
public/images/logo/favicon-640.png
```

建议使用同一张方形 Logo 生成不同尺寸：

| 文件              | 建议用途         |
| ----------------- | ---------------- |
| `favicon-32.png`  | 浏览器标签页     |
| `favicon-96.png`  | 桌面图标         |
| `favicon-256.png` | 通用展示         |
| `favicon-512.png` | PWA              |
| `favicon-640.png` | 大尺寸分享或展示 |

替换后检查：

```js
siteMeta: {
  logo: "/images/logo/favicon-256.png",
  author: {
    cover: "/images/logo/favicon-256.png",
  },
},
```

另外还要检查：

- `public/favicon.ico`
- `themeConfig.mjs` 的 `inject.header`
- `.vitepress/config.mjs` 中的 PWA manifest 图标

第一次替换时，建议保留原文件名，只覆盖图片内容。这样可以避免遗漏引用。

## 六、替换示例文章

当前模板有两篇示例文章：

```text
posts/2026/0907.md
posts/2026/0917.md
```

可以直接修改，也可以新建自己的文章。

### 文章路径

```text
posts/年份/月日.md
```

例如：

```text
posts/2026/1025.md
```

文件路径会生成网址，但文件名不必严格按照日期。为了方便维护，建议使用有规律的命名。

### 文章开头

```yaml
---
title: 我的第一篇文章
date: 2026-10-25
categories: [日常]
tags: [记录, 开始]
description: 这是我发布的第一篇文章，用来介绍我的博客。
top: true
cover: /images/blog/first-post/cover.webp
articleGPT: 这篇文章介绍我为什么开始写博客，以及未来准备记录哪些内容。
---
```

字段说明：

- `title`：文章标题。
- `date`：发布日期，会影响排序和归档。
- `categories`：分类，可以写字符串或数组。
- `tags`：标签，可以写字符串或数组。
- `description`：文章摘要和搜索描述。
- `top: true`：置顶文章。
- `cover`：文章封面。
- `articleGPT`：主题中的摘要组件文案。

::: warning
frontmatter 必须放在文件最前面，并使用成对的 `---`。漏掉结束标记会导致文章无法识别。
:::

### 文章图片

把图片放在：

```text
public/images/blog/first-post/cover.webp
```

正文使用：

```md
![文章封面](/images/blog/first-post/cover.webp)
```

路径必须以 `/images/` 开头，不能使用电脑中的绝对路径。

## 七、修改普通页面

### 1. 关于页面

涉及文件：

```text
pages/about-me.md
.vitepress/theme/views/AboutMe.vue

pages/about-website.md
.vitepress/theme/views/AboutWebsite.vue
```

Markdown 文件主要负责页面入口，具体展示内容位于 Vue 文件中。

第一次修改时：

- 只替换姓名、介绍、域名、邮箱和链接。
- 不要改变 `<template>` 中的标签层级。
- 不要删除 `<script setup>` 和 `<style>`。
- 每修改几行就刷新一次页面。

### 2. 友情链接

涉及文件：

```text
pages/link.md
.vitepress/theme/assets/linkData.mjs
```

在 `linkData.mjs` 中修改：

```js
{
  name: "朋友的博客",
  avatar: "/images/friend/friend.png",
  desc: "朋友的博客介绍",
  url: "https://friend.example.com",
},
```

同时修改 `pages/link.md` 中的友链申请格式和规则。

### 3. 留言板

修改：

```text
pages/hide/message.md
```

可以调整标题、欢迎语、留言规则和隐私说明。页面中的评论区域由评论服务控制。

### 4. 隐私与版权

必须根据实际情况修改：

```text
pages/privacy.md
pages/cc.md
```

隐私政策中应该说明：

- 是否使用评论系统。
- 是否使用访问统计。
- 是否使用搜索服务。
- 是否加载第三方 CDN。
- 是否使用天气、音乐或热榜服务。
- 部署平台可能记录哪些访问数据。

不要直接保留模板中的法律文本而不检查。

## 八、配置第三方功能

### 1. 评论

```js
comment: {
  enable: true,
  type: "twikoo",
  twikoo: {
    js: "https://cdn.jsdelivr.net/npm/twikoo@1.6.42/dist/twikoo.all.min.js",
    envId: "你的 Twikoo 环境地址",
    region: "",
    lang: "zh-CN",
  },
},
```

修改后打开留言板测试。如果暂时没有评论服务，可以将 `enable` 改为 `false`。

### 2. 搜索

```js
search: {
  enable: true,
  appId: "你的 Algolia App ID",
  apiKey: "你的 search-only API Key",
  index: "你的索引名称",
},
```

这里只能填写搜索专用的公开 Key，不能填写管理员 Key。

### 3. 音乐

```js
music: {
  enable: true,
  url: "你的 Meting API 地址",
  id: ["你的歌单 ID"],
  server: "netease",
  type: "playlist",
},
```

第一次配置建议只放一个歌单，确认播放器正常后再调整模式。

### 4. 天气和热榜

复制环境变量文件：

```powershell
Copy-Item .env.example .env.local
```

然后填写：

```text
VITE_WEATHER_KEY=
VITE_HELLOGITHUB_API_URL=
VITE_BETTER_STACK_STATUS_PAGE_URL=
```

所有 `VITE_` 变量都会进入浏览器文件，只能保存可公开的数据。

### 5. 打赏与统计

```js
rewardData: {
  enable: true,
  wechat: "/images/pay/wechat.webp",
  alipay: "/images/pay/alipay.webp",
},
```

统计配置：

```js
tongji: {
  "51la": "你的统计 ID",
},
```

没有这些需求时保持关闭或空值即可。

## 九、修改仓库和部署信息

### package.json

```json
{
  "name": "my-blog",
  "author": "小明",
  "home": "https://blog.example.com",
  "github": "https://github.com/xiaoming/blog",
  "repository": "github:xiaoming/blog"
}
```

### robots.txt

修改：

```text
public/robots.txt
```

将 `https://example.com/sitemap.xml` 改为正式域名。

### 外链中转页

如果启用 `jumpRedirect`，修改：

```text
public/redirect.html
```

其中需要替换：

- 页面标题。
- 站点名称。
- 返回主页链接。
- 域名白名单和黑名单。

### GitHub Pages

检查：

```text
.github/workflows/deploy.yml
```

如果默认分支是 `release`：

```yaml
branches: [release]
```

如果默认分支是 `master`，则保持不变。

## 十、全仓搜索占位内容

修改完主要配置后，在编辑器中全局搜索：

```text
My Curve Blog

hello@example.com
example.com
example.net
example.org
example.dev
example.app
your-name
your-repository
YOUR_ALGOLIA_APP_ID
YOUR_SEARCH_ONLY_API_KEY
your_index_pages
```

每找到一处都要判断它属于：

- 站点配置。
- 示例文字。
- 外部链接。
- 代码示例。
- 测试数据。

不要把代码示例中的示例网址全部误删。

## 十一、发布前检查

执行：

```powershell
pnpm format
pnpm lint
pnpm build
pnpm preview
```

然后逐项检查：

- [ ] 浏览器标题是自己的博客名称。
- [ ] 首页欢迎语已经修改。
- [ ] 生日倒计时显示正确。
- [ ] 时间线内容正确。
- [ ] 顶栏导航链接可以打开。
- [ ] 页脚社交链接正确。
- [ ] Logo 和 favicon 已替换。
- [ ] 示例文章已经修改或删除。
- [ ] 关于页面没有模板文字。
- [ ] 友链信息正确。
- [ ] 隐私政策符合实际情况。
- [ ] 评论、搜索和音乐已配置或关闭。
- [ ] `rss.xml` 和 `sitemap.xml` 使用正式域名。
- [ ] 手机端导航正常。
- [ ] 全仓没有旧域名、私人邮箱和真实密钥。
- [ ] Git 历史中没有需要撤回的敏感信息。

## 推荐的修改顺序

为了减少排查难度，建议按下面的节奏进行：

### 第一阶段：网站身份

修改 `siteMeta`、`since`、`icp` 和 Logo。

### 第二阶段：首页体验

修改欢迎语、生日倒计时、时间线、导航和页脚。

### 第三阶段：内容

修改文章、关于页面、友链、隐私和版权页面。

### 第四阶段：功能

逐个配置评论、搜索、音乐、天气、统计和打赏。

### 第五阶段：部署

修改仓库地址、robots、redirect 和 GitHub Pages 分支，最后执行完整构建。

---

## 总结

看到这篇文章时，开发环境已经准备好了。接下来真正需要做的是替换内容，而不是修改主题结构。

最小可用博客只需要完成：

1. 修改 `siteMeta`。
2. 修改生日和首页欢迎语。
3. 修改导航和页脚。
4. 替换 Logo。
5. 发布一篇自己的文章。
6. 执行 `pnpm build`。

完成这些以后，你已经有一个属于自己的博客。评论、搜索、统计和音乐等功能可以在此基础上继续添加。

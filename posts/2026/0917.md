## 为什么要重视文章结构

博客主题可以提供漂亮的样式，但读者真正留下来，通常是因为文章清楚、有用、容易阅读。

一篇文章如果只有标题和几段零散文字，读者很难判断：

- 这篇文章讲什么。
- 我是否需要继续读。
- 重点在哪里。
- 读完后我能做什么。

因此，写文章时建议先规划结构，再填充内容。

## 一、先确定读者和目标

写之前先问自己三个问题：

1. 这篇文章面向谁？
2. 读者看完后应该学会什么？
3. 读者是否需要提前安装工具或准备资料？

例如，一篇面向零基础读者的教程，应该：

- 解释专有名词。
- 给出完整命令。
- 告诉读者应该在哪个文件中修改。
- 预测常见错误。

## 二、使用清晰的标题层级

推荐的标题层级：

```md
# 文章标题

## 一级章节

### 二级小节

#### 需要补充的细节
```

实际写作时，Markdown 文件的 `title` 已经是文章标题，因此正文通常从 `##` 开始。

::: tip 标题建议
标题应该表达具体结果，例如“如何添加文章封面”，而不是只写“说明”或“补充”。
:::

## 三、合理使用段落

段落之间空一行。一个段落尽量只讲一个重点。

不推荐：

```text
这篇文章会介绍 Markdown 还有代码块还有图片还有分类标签还要说明部署和常见问题这些内容都很重要。
```

推荐：

```text
这篇文章会介绍 Markdown 的常用语法。

我们会重点练习标题、列表、引用、代码块和图片，并在最后完成一次发布前检查。
```

## 四、列表：用于步骤和并列信息

有序列表适合步骤：

```md
1. 打开 `posts/` 目录。
2. 新建一个 Markdown 文件。
3. 编写 frontmatter。
4. 保存并预览。
```

无序列表适合并列信息：

```md
- 文章标题
- 发布日期
- 分类和标签
- 文章摘要
```

不要把完整的段落硬塞进列表。列表中的每一项最好保持简短。

## 五、引用：突出观点或提醒

引用适合放作者观点、总结或需要注意的内容：

```md
> 模板只是起点。真正属于你的博客，是从第一篇原创文章开始的。
```

如果需要强烈的提醒，使用提示容器：

```md
::: warning 注意
不要把管理员 Token 或数据库密码写入 `.env.local`。
:::
```

常用容器：

- `::: tip`：提示。
- `::: info`：信息。
- `::: warning`：警告。
- `::: danger`：危险操作。
- `::: details`：默认折叠的补充内容。

## 六、表格：比较多个项目

表格适合展示字段、命令和对比信息：

| 字段          | 作用                | 是否必需 |
| ------------- | ------------------- | -------- |
| `title`       | 文章标题            | 是       |
| `date`        | 发布日期            | 是       |
| `categories`  | 文章分类            | 建议填写 |
| `tags`        | 文章标签            | 建议填写 |
| `description` | 列表摘要和 SEO 描述 | 建议填写 |

表格不要放太多长段落，否则在手机端很难阅读。

## 七、代码块：展示可以复制的内容

行内代码使用一个反引号：

```text
使用 `pnpm dev` 启动开发服务器。
```

多行代码使用三个反引号，并标注语言：

````md
```bash
pnpm install
pnpm dev
```
````

代码块中的命令应该保持可以直接复制。不要把说明文字和命令混在同一行。

## 八、链接和图片

站内链接：

```md
[文章归档](/pages/archives)
```

外部链接：

```md
[VitePress Markdown 指南](https://vitepress.dev/zh/guide/markdown)
```

图片放在 `public/` 下：

```text
public/images/blog/markdown-guide/cover.webp
```

然后引用：

```md
![Markdown 封面](/images/blog/markdown-guide/cover.webp)
```

图片要有替代文字。替代文字可以帮助读者理解图片，也能提升无障碍体验。


### 分类和标签怎么选

分类表示文章所属的大方向，标签表示文章中的具体主题。

例如：

```yaml
categories: [写作指南]
tags: [Markdown, 结构, 读者体验]
```

不要为了数量而堆砌标签。通常一篇文章使用 2 至 5 个标签更容易维护。

### 摘要怎么写

`description` 应该回答“这篇文章能帮助读者解决什么问题”。

不推荐：

```yaml
description: 这是一篇关于 Markdown 的文章。
```

推荐：

```yaml
description: 学习标题、列表、代码块和图片的使用方法，写出结构清楚、读者容易理解的博客文章。
```

## 十、文章写作流程

### 1. 写提纲

先写出章节标题：

```md
## 这篇文章解决什么问题

## 需要提前准备什么

## 具体操作步骤

## 常见问题

## 总结
```

### 2. 填充内容

每个章节只完成一个目标。需要展开时使用三级标题。

### 3. 检查阅读顺序

从上往下读一遍，确认读者不会在中间突然遇到没有解释的概念。

### 4. 检查代码和链接

- 命令是否可以直接复制。
- 文件路径是否真实存在。
- 链接是否能够打开。
- 图片是否能够显示。

### 5. 发布前预览

执行：

```bash
pnpm dev
```

在桌面端和手机端分别检查一次。

## 十一、一个完整的文章模板

```md
---
title: 文章标题
date: 2026-10-25
categories: [分类]
tags: [标签一, 标签二]
description: 一句话说明文章解决的问题。
top: false
cover: /images/blog/example/cover.webp
---

## 这篇文章解决什么问题

说明读者为什么需要这篇文章。

## 需要提前准备什么

- 准备项目一
- 安装工具二
- 了解基础概念三

## 具体步骤

### 第一步

说明操作，并给出代码或图片。

### 第二步

继续说明操作。

## 常见问题

### 问题一

说明原因和解决办法。

## 总结

回顾重点，并给出下一步建议。
```

## 十二、发布前检查清单

- [ ] 标题是否准确表达文章内容
- [ ] 第一段是否说明文章目标
- [ ] 标题层级是否清楚
- [ ] 是否解释了专有名词
- [ ] 代码命令是否可以复制
- [ ] 图片是否有替代文字
- [ ] 站内链接和外部链接是否有效
- [ ] 分类和标签是否合理
- [ ] `description` 是否具体
- [ ] 手机端是否容易阅读
- [ ] 是否检查过错别字
- [ ] 是否运行过 `pnpm build`

## 总结

Markdown 不只是排版工具，它也是帮助你组织思想的工具。

对于零基础作者，可以先遵循一个简单原则：

> 先告诉读者要解决什么问题，再一步一步告诉读者怎么做。

当文章结构稳定后，再逐步增加图片、代码示例和深入分析，读者体验会比一开始就堆砌功能更好。
